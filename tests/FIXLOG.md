## 2026-08-08 — ANTONY_DECISIONS item 16 ("fix both bugs and add all four features")

- CONF-structure-repeats-4 (the "volta-33 sentinel" bug): `mkBarline` applied `ending.replace('-', ',')` BEFORE testing for a quoted string, so volta TEXT was mangled (`"4.-5."` -> `4.,5.`); the comma rewrite now happens only on the numeric-list branch. The fake sentinel `number='33'` for a text-only ending is replaced by the EMPTY MusicXML ending-number (the `ending-number` simple type is `([ ]*)|([1-9][0-9]*(, ?[1-9][0-9]*)*)`, so '' is the canonical text-only value); '33' collided with a real 33rd ending and lied to every downstream consumer. Because '' is falsy, the open-volta sentinel changed from `''` to `None` and the stop guard from `if s.curVolta:` to `if s.curVolta is not None:` — otherwise a text-only volta would never have been closed. Functions touched: `mkBarline`, `Music.reset` (curVolta init), `mkPart` (per-voice curVolta reset).

- CONF-structure-repeats-3 follow-up (the "%%tocoda target attribute" bug): `%%tocoda NAME` emitted `<sound coda="NAME">` — the attribute that LABELS a coda section — instead of `<sound tocoda="NAME">`, the JUMP target. A "To Coda" instruction therefore read to every consumer as a coda marker sitting at the jump. One-word fix. Functions touched: `doField_I` (tocoda branch).

- CONF-dynamics-directions-tempo-1 (metric modulation): `Q:a/b=c/d` is a note-equals-note modulation, but the per-minute regex's `(\d[.\d]*)` branch read the '3' of '3/8' as a tempo of 3 per minute — `<sound tempo="3.00">`, near-frozen and effectively silent. A dedicated `(\d+)/(\d+)\s*=\s*(\d+)/(\d+)` match is now tried FIRST and emits the MusicXML metric-modulation form: a `<metronome>` with TWO `<beat-unit>` groups (dots included) and no `<per-minute>`. The playback tempo is computed relatively — the right-hand note now lasts as long as the left-hand one did, so qpm scales by (c/d)/(a/b) — carried in a new `s.lastQpm` so chained modulations compose. NOTE: OPUS_MIDI_COMPILER_V2_SPEC §5 assigns "correct beat-unit arithmetic" to the compiler; done here as well because the compiler's loader reads only `<sound tempo>` and would otherwise silently hold the previous tempo through a modulation. Functions touched: `doTempo`, `Music.reset` (lastQpm init).

- CONF-abcplus-extensions-1 (`%%mute` vs hand stop): `%%mute` has no measure to attach to when it appears in a header, so it is DEFERRED to the next note as a decoration token — and the bare token `'mute'` is also the `tecMap` key for the `!+!`/hand-stop articulation, so the directive was consumed as `<stopped/>` and the documented `<sound mute="yes">` was unreachable. The directive now defers under the non-colliding token `sound-mute` / `sound-mute-off`. Deliberately NOT done: removing `'mute':'stopped'` from `tecMap`. The `!mute!` note decoration is documented as a mute directive (abc-plus `CHECKLIST.md` line 236) and is consumed by `staffDecos` before `tecMap` is ever reached; the `staffDecos` branch keeps accepting the bare tokens so `!mute!` output is byte-identical to before. `!plus!` / `!+!` remain the `<stopped/>` hand stop. Functions touched: `doField_I` (the swing/mute deferral), `staffDecos` (mute branch).

- CONF-ornaments-3 (single-note tremolo): the slash and `trem<N>` forms stopped at THREE beams; MusicXML `tremolo-marks` is 0..8. Both forms now run to eight via `^/{1,8}$` and `^trem[1-8]$`. The two-note duplet branch (`'/-'`,`'//-'`,`'///-'`,`'////-'`) is tested first in the same elif chain, so `!////-!` still means the two-note form. Functions touched: `staffDecos` (tremolo branches).

- CONF-abcplus-extensions-2 (header-form banks): two independent losses. (1) `splitHeaderVoices` moved only `I:MIDI`-prefixed header fields out to travel with their voice, and the test was case-SENSITIVE, so `%%midi-bank` / `%%midi-vol` / `%%midi-pan` (which become `I:midi-...`) stayed in the header, lost the voice they belonged to and were dropped — now `x[:6].upper() == 'I:MIDI'`. (2) the `%%MIDI ...` branch had regexes for program/channel/drummap/control but none for `bank`, so the word form `%%MIDI bank N` was silently ignored — added `r5 = re.search(r'\bbank +(\d+)', x)` wired into the same instrument-change path as the others. Functions touched: `splitHeaderVoices`, `doField_I` (the MIDI branch).

## 2026-08-29 — the measure-numbering enum ("Dorico refuses every file")

- `<measure-numbering>yes</measure-numbering>` is not MusicXML — the enum is `none|measure|system` in every version of the spec, and the emitter wrote the internal state string straight into the element (doubly wrong: an author's correct `%%measurenumbering system` was folded back to `yes` by the same line). MuseScore's importer silently dropped the invalid value and used its per-system default, so every engraving looked right; Dorico schema-validates and refused the file (first seen on `the_weir_and_the_wide_water_transposed.musicxml`, 2026-08-29 — 4,000 occurrences, one per measure per part). Estate spread at discovery: 162 files in `AOS packs for IGCSE Music/`, 75 live. Fix: the emitter normalises to the enum (`yes/1/true/on`→`system`, matching what MuseScore had been rendering; explicit `none|measure|system` pass through; else `none`), and both `barnumbers` handlers parse their actual argument token (was `'1' in fld`, which matched `10`). The per-measure emission cadence is left alone — schema-legal, and its own question. Functions touched: `mkMeasure` (emitter + inline peek), `doField_I` (barnumbers), `staffDecos` (measurenumbering now passes the raw value).
- Suite: the three hand guards that ASSERTED the invalid value (`[text()='yes']: 4` on p19/p21/barnumbers_header) now assert `[text()='system']: 4` **plus `[text()='yes']: 0`**, so a regeneration can never re-bless the old output. Falsification run: `ABC2XML_BIN=abc2xml/abc2xml.py.pre-dorico-enum-2026-08-29` fails exactly p19, p21, barnumbers, barnumbers_header (137 PASS / 4 FAIL) — the guard can go red.
- Housekeeping the regeneration forced: OVERRIDES still carried 12 stale xfail rows for bugs fixed earlier in this campaign (CONF-lines-1, CONF-ornaments-1, CONF-articulations-breaths-1/2, CONF-structure-repeats-1/2/3, CONF-pitch-staff-1/2/3/4 — the CONF-ornaments-2 entry above records working AROUND this instead of clearing it, by hand-restoring expected.json). Regenerating re-listed all 12 as xfail, and an XPASS cannot exit 1 — the 12 fixes would have been unguarded. Their attr/text desired-counts are migrated to EXTRA_KEYS as permanent baseline guards and the stale rows deleted. Suite: 160 probes | PASS 141, FAIL 0, XFAIL 19, XPASS 0 — same headline as 2026-08-08, now actually coherent with its generator.
